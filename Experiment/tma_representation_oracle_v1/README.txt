TMA 表示信息事后审计 v1

目的
  判断崩溃类在源编码器的冻结特征里是否仍可识别，并将三种可能分开：
  付费标签/选样不足、编码器丢失可用信息、查询到未来测试之间继续漂移。
  这不是新方法的性能试验，也不在 1000 标签预算内。

服务器运行
  cd /data/xjw/traffic-drift2
  git pull
  python -u Experiment/tma_representation_oracle_v1/audit.py

查看结果
  cat /data/xjw/tma-care-data/pilot_v1/representation_oracle_v1/source_0/REPORT.txt
  机器可读数据在同目录 scores.csv。

检查完全相同的特征是否跨时间重复（只读，无需重新拟合模型）
  python Experiment/tma_representation_oracle_v1/feature_overlap.py
  若未来样本大量与查询期 1--10 日的 16 维特征完全相同，接近 1 的 AP
  可能反映重复设备流量模式；不应直接当成跨环境泛化证据。

协议
  复用完成的 pilot 缓存、源模型与源期预处理，不重新下载/prepare/训练源模型。
  事后使用查询池的全部真实标签，按时间将当月 1--10 日作拟合样本、
  11--14 日作查询侧检查，16 日起作未来评价。每个崩溃类是一个二分类问题。
  同一批拟合 ID（所有正类、最多 20 倍负类）用于原始预处理特征和冻结编码
  特征，分别拟合固定配置的线性逻辑回归、非线性直方图梯度提升树。
  源模型原始类别概率作参照。报告 AP、AUROC、正类数和正类占比。
  被检查的类是看过先前结果后选出的：3 月 5/22/26/37，4 月 20。

读结果时
  若冻结特征模型在查询检查和未来评价上均有高 AP，说明有可用的二分类
  信息，先查标签数量、选样与训练目标；不能仅因 CARE 失败就更新编码器。
  若原始特征上的同类模型持续优于冻结特征，提示源编码器可能丢失可用信息，
  仍需要匹配容量、更多源种子和独立数据排除模型选择差异。
  若查询侧高、未来评价低，优先考虑月内时间变化。
  两种特征都低，不能证明问题本质上不可解，可能是这 16 个统计字段不足。
  AP 的随机基线是该集合正类占比；二分类 AP 不能与原稿多类 F1 比分数，
  也不能保证相同标签预算下多类修复成功。

限制
  查询池真实标签远多于 1000 付费标签，属于事后多标签诊断。
  所有目标月份已被看过，不是独立验证。不可把结果当部署性能，
  不可据此在同一月份继续调参再声称发现有效新方法。
