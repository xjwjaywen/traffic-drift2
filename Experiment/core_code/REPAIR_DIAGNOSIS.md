# 修复预演的损伤预测诊断

这是已完成 `kbs_repair_aware_v1` 的事后诊断。问题是：800 个共同查询训练出的预演模型，能否定位最终修复会改错的样本？以及侦察中确认的错分关系，是否确实指向需要保护的区域？

以最终 **BADGE** 修复为主要参照，其他三组作为敏感性分析。所有组都使用原实验每个种子的四组查询并集排除评估集。只读取保存的预测、查询、缓存标签和源 logits；不训练、不做模型推断、不增加查询或标签，也不修改原实验文件。

## 服务器运行

在原 `traffic-ncde` 环境、仓库根目录运行：

```bash
bash Experiment/core_code/scripts/run_kbs_repair_diagnosis.sh run
cat Experiment/core_code/outputs/kbs_repair_diagnosis_v1/report.md
```

`plan` 打印诊断定义；`preflight` 只核验原实验完整性；`run` 包含相同核验并生成报告。直接运行 `run` 即可。启动器强制 CPU，不受 `GPU_ID`、`DEVICE`、旧 `SEEDS` 或 `REPAIR_SEEDS` 环境变量影响，分析原 manifest 中的全部种子。`DIAG_THREADS` 默认为 8。

默认输入：

- `outputs/kbs_repair_aware_v1`：共同预演、四组最终预测及已完成评价。
- `outputs/kbs_supplement_v1`：原协议和保存的 BADGE 查询。
- `outputs/kbs_supplement_v1/cache`：缓存及完整性清单。
- `outputs/tls22_cnn/best_model.pt`：只核验哈希。

路径相对于 `Experiment/core_code`。启动器可用 `REPAIR_OUTPUT_DIR` 指定输入 pilot，用 `REPAIR_DIAG_OUTPUT_DIR` 指定新的诊断目录；`STUDY_DIR`、`CACHE_DIR`、`CHECKPOINT` 沿用已有含义。诊断输出必须与输入目录分开，不能互为父子目录。

先核验缓存、代码、原环境版本、所有选择/训练/评价文件的哈希与身份；任何原阶段缺失或文件不一致都会停止。核验大型缓存会产生磁盘读取。随后以 mmap 读取 target 缓存，仅访问标签和保存的 logits，不访问特征张量。使用原实验环境可避免 NumPy/PyTorch 版本不同导致身份核验失败。

脚本还会重新核对侦察标签、错分矩阵、冻结查询、训练查询标签，并把重算的 F1、崩溃数、负翻转数与原评价逐项对齐。运行中断后可重跑；已完成且核验通过的报告直接复用，不重新加载数组。不要手工编辑已完成输出文件，否则完整性核验会拒绝复用。

## 指标和分母

记共同评估集为 E，源预测为 h0、预演预测为 hp、最终预测为 hf，真值为 y：

- **预演翻转区域 F**：h0 ≠ hp。这个标记不需要标签。
- **最终负翻转 N**：h0 = y 且 hf ≠ y，即原本正确、修复后错误。
- **预演负翻转 P**：h0 = y 且 hp ≠ y。它需要事后真值，只用于诊断，不能直接用于选样。
- **区域精确率**：|F ∩ N| / |F|。
- **损伤覆盖率**：|F ∩ N| / |N|。
- **随机基率**：|N| / |E|。这是同一范围内均匀查询一个样本的精确期望，不是随机策略重新训练的效果。
- **富集倍数**：区域精确率 / 随机基率。
- **预演误伤持续率**：|P ∩ N| / |P|。它回答“预演已经改错的样本，有多少最终仍然改错”。

所有集合均限制在 E 内。全样本与原协议固定的非崩溃类分别报告；非崩溃类的真值分组仅作事后分解。由于 N 中源预测一定正确，F 对 N 的覆盖与 P 对 N 的覆盖数学上相同，不能作为两个独立证据。

区域组成另分为：全部、预演翻转、预演不变、已确认关系翻转、未确认关系翻转、事后预演负翻转。已确认关系沿用原定义 `scout_counts[hp, h0] > 0`，只在翻转区域内判断。分别统计预演误伤、预演纠错、从一个错误变成另一个错误，以及最终误伤/纠错。

“已确认吸收者”指在共同侦察中接收过至少一次错分的类。报告其最终误伤占比、源模型原本正确样本的暴露占比、条件误伤率及相对于其他类的风险比。流量大的类会自然贡献更多误伤，不能仅凭误伤数量推断高风险；逐类支持数也必须一起看。没有暴露或零分母的比率记为空值，不填成零或无穷。

## 输出

默认写入独立的 `outputs/kbs_repair_diagnosis_v1`：

| 文件 | 内容 |
|---|---|
| `report.md` | 中文汇总、指标定义及判读边界 |
| `by_seed.csv` | 每种子、最终方法、范围的覆盖/富集/持续率与暴露调整分析 |
| `summary.csv` | 上表的均值、样本标准差、每个指标的有效种子数 |
| `cohorts.csv` / `cohort_summary.csv` | 候选区域组成及最终损伤 |
| `per_class.csv` | 全部类别的支持数、前后 F1/召回率、正负翻转、新崩溃和侦察计数 |
| `transitions.csv` | 每条实际负翻转 a→v 的数量、预演覆盖、相同错误终点及反向侦察关系 v→a |
| `resolved_config.json` / `complete.json` | 定义、来源身份和输出哈希 |

先看 BADGE 的覆盖率和富集倍数，再看已确认关系区域是否比未确认区域更富集最终误伤。区域很大可能带来高覆盖但低精确率；高富集但低覆盖也可能漏掉主要损伤。其他三组使用不同的最终模型，只作敏感性对照。

这轮不搜索新阈值、不增加种子、不自动宣布成功或显著性。种子共用同一源模型和 M12，结果属于开发性诊断。即使损伤预测准确，也尚未证明查询这些点能减少最终损伤，更不能据此认定方法新颖性。
