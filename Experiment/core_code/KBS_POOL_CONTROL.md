# 固定风险候选池的抽样对照

这是一轮有界的开发性实验，不训练模型。原分歧选样已经完成，诊断表明需要先检查候选池到专项抽样之间的损失，再决定是否继续开发该分支。

## 已有证据与本轮问题

服务器五种子诊断（用户回传的均值，原始服务器文件仍需归档）：

- 参考留出集头准确率 0.904、原型准确率 0.445；原型在参考期已经偏弱，不能把问题全部归因于时间漂移。
- 风险候选池平均 20,000 行、727.6 个崩溃类样本，比例 3.638%；无风险候选池仅 35.2 个、0.176%。风险代理在候选池阶段确实富集了这些样本，但不等于能可靠识别真实崩溃。
- 原风险方案的 500 个专项查询中仅有 4.0 个崩溃类样本，比例 0.8%；共享随机探索中有 12.0 个，比例 2.4%。损失发生在池内抽样阶段，尚不能仅凭这张表区分分数权重、几何距离或两者交互的影响。
- 若在每个原风险池均匀抽 500 个，条件期望均值为 18.19 个崩溃样本；加共享探索的均值 12.0，期望总数为 30.19。这是解析期望，不是已跑结果，仍低于原 BADGE 的 44.4。
- BADGE 前 200 个查询平均确认 124.2 个错误、110.2 个不同错分对。许多对只有一个观察值，不能据此声称已学到可靠的错分关系图或邻域检索规则。

本轮只回答：**在同一个风险候选池内，改用均匀、分数或距离抽样，能否避免原组合抽样丢失崩溃样本？**

## 冻结协议

| 方法 | 池内采样质量函数 | 共享部分 |
|---|---|---|
| original_risk | 原分数 × 到已选样本的最小平方距离 | 原结果直接复用，并重建校验查询顺序 |
| pool_uniform | 常数 1 | 相同候选池、随机探索、预算 |
| pool_score | 原风险分数 | 相同候选池、随机探索、预算 |
| pool_distance | 到已选样本的最小平方距离 | 相同候选池、随机探索、预算 |
| badge / random | 原已存全预算查询 | 仅作外部参照，不共享候选池 |

- 原预算通常为 1,000；前三个新对照仍用原 500 个随机探索行和 500 个专项名额。所有数字从原协议读取，测试可使用更小预算。
- 原型仍由原协议每类五个参考样本构造；温度、风险强度、候选池上限和截断排序保持不变。风险仍是预测频率下降代理，并非原稿完整五信号监测器。
- 选择进程加载原缓存后立即丢弃捆绑的目标标签，选择 API 不接受目标标签或崩溃类集合。参考标签仅用于原五样本原型。
- 重建原风险池，验证原型行、风险值、已存推断类别/分数、池大小、原专项查询的池成员资格，并逐行复现原分数×距离查询顺序。任一不一致即停止。
- 原始 pilot 的 device、batch size、threads、代码、NumPy/PyTorch 版本及输入身份必须匹配。默认继承原值；不同的数值设置会被拒绝，避免把池重建差异引入对照。
- 三个新对照用 `seed+2003`，先消耗并校验原探索 RNG 抽样，再逐次无放回查询。距离使用归一化特征的 `max(2-2*cos,0)`，首次距离为 1；剩余距离全为零时回退到基础权重（距离对照为均匀），保证不重复。
- 若正分数候选不足，所有对照选完同一候选池并复用原随机补足行。不得增加标签预算。候选池和查询 ID、分数及原型推断随输出保存，不保存目标标签。
- 所有请求种子的选择完成后，launcher 才开启另一个 Python 进程读取目标标签并生成报告。不自动训练、筛选赢家或调参。

## 服务器运行

在 `traffic-ncde` 环境和仓库根目录执行。输出是独立兄弟目录，旧结果不会重算或覆盖。

```bash
cd /data/xjw/traffic-drift2
conda activate traffic-ncde
env -u http_proxy -u https_proxy -u all_proxy \
    -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY \
    git -c http.proxy= -c http.https://github.com.proxy= -c remote.origin.proxy= \
    pull --ff-only origin main
```

确认拉取成功后：

```bash
nohup bash Experiment/core_code/scripts/run_kbs_pool_control.sh run \
  > kbs-pool-control.log 2>&1 &
tail -f kbs-pool-control.log
```

`Ctrl+C` 只退出 `tail`；看到 `Results: .../evaluation/report.md` 表示流程完成。输入哈希校验和特征加载可能暂时没有新日志；本轮没有优化器训练步。

```bash
cat Experiment/core_code/outputs/kbs_pool_control_v1/evaluation/report.md
cat Experiment/core_code/outputs/kbs_pool_control_v1/evaluation/paired_by_seed.csv
```

可选先执行 `plan`（不读缓存）或 `preflight`（验证输入，读取原设置）。`run` 自动依次执行 `select`、`evaluate`，选样失败立即停止，评价不会启动。中断后原命令会复用已验证完成的种子；哈希损坏或协议变化会报错，不会静默覆盖。

路径选项：`STUDY_DIR`、`CACHE_DIR`、`PILOT_DIR`、`CHECKPOINT`、`POOL_OUTPUT_DIR`。默认读取原 pilot 全部种子；`POOL_SEEDS=0,1` 可设子集，但必须使用新输出目录，不能把子集结果当作五种子证据。旧 `SEEDS`、`PILOT_SEEDS`、`DIAG_SEEDS` 不改变本轮种子。`GPU_ID` 可选择 GPU；显式 `DEVICE` / `--batch-size` / `--threads` 必须与原 pilot 匹配。

## 输出与判读

`outputs/kbs_pool_control_v1/`：

- `pool_control_manifest.json`：冻结的原 pilot、原选择/评价与实现哈希及协议。
- `seed_N/selection.json` / `candidate_pool.json`：所有选择及同一候选池；`complete.json` 最后写入并记录各文件哈希。
- `seed_N/common_excluded_ids.json`：原六方法与新增三方法查询的并集。未来若比较修复 F1，须在这个共同排除集上重算基线和所有新模型，不能直接拼接旧汇总。
- `evaluation/summary.csv`：各方法全预算与探索/专项/补足分阶段统计，以及固定风险池统计；各项均值和样本标准差。
- `by_seed.csv`、`per_class.csv`：逐种子计数与全部类别（含零支持行）。
- `paired_by_seed.csv`：三个新方法各自减原风险方案（全预算及专项），以及减 BADGE（全预算）。
- `uniform_expectation.csv`：给定每种子固定候选池的均匀专项抽样条件期望，与实测结果明确区分。
- `report.md`：主要观察，无自动“成功/失败”或显著性标签。原 BADGE/random/risk 全预算指标先与旧评价对账。

先比较每个种子的专项崩溃类数量/比例与覆盖，再看总查询覆盖及 BADGE 差距。若均匀或分数对照恢复候选池中的信号，这只定位了抽样损失，仍需考察是否值得进入修复训练；如果总表现仍落后 BADGE，不将其包装为更好的选样方法。四组结果可能存在分数与距离交互，不能无条件给出单一因果归因。

若没有稳定收益，停止这条分支，不继续在 M12 上网格搜索权重/阈值。下一条独立假设可考虑用预算内已确认的目标错误引导检索，并设置随机/打乱错误种子等对照；当前脚本没有实现或验证这种方法。

本轮由已经观察过的 M12 结果启发，是开发性探索。五个原型/选样种子不是五个独立模型或月份；查询到更多错分不等于修复 F1 更高，也不说明没有新崩溃。候选方案冻结后必须使用未参与选方案和调参的数据验证。简单替换抽样规则或二阶段流程本身不构成创新证明。
